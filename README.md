# PlotMaster

**Линейный агент визуализации данных.** Реализован без LangChain/SDK, но с интерфейсами `run(input) -> output`, аналогичными `Runnable` из LangChain — систему легко перенести в LangChain при необходимости.

Агент принимает табличный датасет и запрос на естественном языке, сам решает, нужен ли предварительный анализ данных, планирует графики и интерпретирует результат.

## Как это работает

```
main.py → VisualizationPipeline
              ├── Analyst        (нужен ли анализ + код шагов анализа)
              ├── Planner        (какие графики и с какой семантикой)
              └── Interpreter    (ответ пользователю по итогам)
```

Все агенты общаются с LLM через единый `LLMClient`, который поддерживает два бэкенда:

- **OpenRouter** — облачный, по умолчанию модель `openrouter/auto`;
- **Ollama** — локальные модели (список подтягивается автоматически).

## Компоненты

| Файл | Роль |
|---|---|
| `main.py` | CLI-точка входа: загрузка датасета (`csv`/`xlsx`/`json`/`parquet`), выбор бэкенда, запуск пайплайна, вывод графиков и метрик |
| `pipeline.py` | Линейный пайплайн: анализ → планирование → исполнение → интерпретация |
| `agents/analyst.py` | Решает, нужен ли предварительный анализ; генерирует YAML-контракт и python-код для каждого шага; умеет чинить упавший код через `fix_code` |
| `agents/planner.py` | Определяет, какие графики нужны и с какой семантикой; не знает о библиотеках и backend'ах; список доступных `chart_type` и их defaults подтягивается из `registry/` |
| `agents/interpreter.py` | Превращает `VisualizationReport` + `DatasetContext` в текстовый ответ; поддерживает стриминг токенов |

## Запуск

```bash
pip install -r requirements.txt

python main.py --data path/to/data.csv --prompt "Построй распределение target по классам"

# или интерактивно (спросит бэкенд, модель и промпт)
python main.py --data path/to/data.csv
```

Полезные флаги:

- `--backend {openrouter,ollama}`, `--model`, `--api-key`
- `--output-dir` — куда сохранять графики (по умолчанию `output/`)
- `--no-analysis` / `--no-interpreter` — отключить соответствующие этапы
- `-s/--streaming` — печатать ответ по токенам
- `--verbose` — DEBUG-логи
- `--code` / `--code-description` — подсказать Analyst'у пользовательский модуль с классами/функциями

## Особенности

- **Без LangChain**, но интерфейсы совместимы с `Runnable` — легко мигрировать.
- **Разделение ответственности**: Planner не знает про библиотеки, Analyst — про графики, Interpreter — про планирование.
- **Реестр** (`registry/`) изолирован от построения моделей и хранит доступные `chart_type` с их defaults, что позволяет добавлять новые типы графиков без правок промптов.
- **Самопочинка кода**: если сгенерированный Analyst'ом шаг анализа падает в песочнице, `fix_code` переспрашивает LLM с текстом ошибки.
- **Стриминг** ответа Interpreter'а через генератор.
